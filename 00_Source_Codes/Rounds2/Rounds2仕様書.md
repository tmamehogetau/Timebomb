# Rounds2 仕様書

Draft v0.2

## 1. ゲーム概要

### 1.1 ジャンル / コンセプト

- PvP ローグライトアクションシューティング。
- 視点はトップダウン固定。
- 精密な撃ち合いだけではなく、カードの組み合わせによってカオスな盤面が発生するパーティ寄りの対戦ゲームを目指す。
- ビルドの面白さは、マッチ中にカードを積み重ねていくことで生まれる。

### 1.2 最大人数 / 対戦形式

- 最大 4 人。
- 対戦形式:
  - 1v1
  - 最大 4 人 FFA
  - チーム戦
  - 非対称チーム戦

### 1.3 MVP / 初期実装の優先度

- 最優先は 1v1。
- 次点で 2v2 チーム戦。
- FFA と 1v3 などの非対称チーム戦は、基礎が固まった後に拡張する。

---

## 2. プラットフォーム / 技術方針

### 2.1 プラットフォーム

- Windows 専用。

### 2.2 技術構成

- エンジン: Unity
- 言語: C#
- ネットワーク: FishNet
- 構造: Dedicated Server
- 方針: サーバー権威

### 2.3 サーバー / 接続

- 初期実装では、ローカル PC 上で Dedicated Server を起動し、クライアントが IP 入力で直接接続する。
- 部屋リスト、マッチメイキング、外部サービス連携は初期範囲外。
- 将来的にクラウド上の常設 Dedicated Server を検討する。

### 2.4 ネットワーク同期

- 命中判定はサーバーが確定する。
- クライアントには演出用の予測を許可する。
- 初期実装ではサーバーが弾を生成し、全クライアントへ同期する。
- 操作感が悪い場合は、クライアント側に演出用ローカル弾を追加する。
- 初期実装ではラグ補償なし。サーバー現在位置で判定し、必要なら後から追加する。
- サーバー tick rate は調整前提。初期仮値は 60 tick/s。
- 初期実装では自キャラも敵も補間のみで表示する。操作感が悪ければ、自キャラのクライアント予測とサーバー補正を追加する。

### 2.5 物理処理

- Unity 標準物理を使う。
- 移動、衝突、ノックバックなど重要な値はサーバー側で決定する。

## 3. 視点 / 操作

### 3.1 視点

- トップダウン固定。
- マップ全体は常に 1 画面に収まる。
- 16:9 を主軸にしつつ、安全領域を設けて複数画面比率に対応する。

### 3.2 操作デバイス

- 初期実装はキーボード + マウス。
- ゲームパッド対応は後から追加する。

### 3.3 標準キー設定

- キー変更可能にする。
- 標準設定:
  - WASD: 移動
  - マウス: エイム
  - 左クリック: 射撃
  - 右クリック: シールド

### 3.4 基本操作

- 移動
- エイム
- 射撃
- サブ行動

### 3.5 サブ行動: シールド

- 初期サブ行動はダッシュではなく、シールドとする。
- シールドは一瞬だけ無敵になるバリアを発生させる。
- シールド中は移動可能、射撃不可。
- シールドは基本的に全ダメージを防ぐ。
- 状態異常などの扱いはカードや効果ごとに個別定義する。
- 弾がシールド中のプレイヤーに当たった場合、基本は弾が消滅し、ダメージは防がれる。
- 反射などの追加効果はカード効果で付与する。
- シールドの無敵時間は調整前提。初期仮値は 0.35 秒。
- シールドのクールダウンは調整前提。初期仮値は 4 秒。
- サブ行動を置換するカードは登場しない。
- サブ行動カードは、シールドに効果を追加または強化するもののみとする。

## 4. マッチ構造

### 4.1 用語

- マッチ: 試合全体。
- ラウンド: セット勝利を競う単位。
- セット: 戦闘単位。

### 4.2 マッチ勝利条件

- 先に 5 ラウンド勝利したプレイヤーまたはチームがマッチ勝利。
- 必要ラウンド勝利数はロビー設定で変更可能。

### 4.3 ラウンド勝利条件

- 1 ラウンドは 2 セット先取。
- 最大 3 セット制ではなく、誰かまたはどちらかのチームが 2 セット勝利するまで続行する。
- 引き分けセットは 2 本先取のカウントに含めない。
- 引き分け時はどちらのセット勝利数も増えず、再セットを行う。

### 4.4 セット勝利条件

- FFA では、最後まで生き残った 1 人がセット勝利。
- チーム戦では、相手チームを全員脱落させたチームがセット勝利。
- 時間切れ判定は作らず、収縮する外周境界によって必ず決着させる。

### 4.5 同時死亡

- 同じサーバー tick 内で全員、または両チームが全滅した場合、そのセットは引き分け。

### 4.6 セットフロー

1. マップ選択
2. スポーン
3. ビルド適用
4. セット開始カウントダウン
5. 戦闘
6. 撃破されたプレイヤーは脱落
7. セット勝利条件達成で終了
8. ラウンド勝利条件を確認
9. 必要に応じて Draft または次セットへ進行

### 4.7 死亡 / 観戦

- 死亡後はそのセット中に復活しない。
- 次セット開始時に復帰する。
- 脱落後も通常と同じ定点見下ろし視点のまま観戦する。
- 観戦中は操作不可。
- 観戦中も生存中と同じ情報を表示する。

### 4.8 途中参加 / 切断

- マッチ中の途中参加はプレイヤーとして許可しない。
- 参加できる場合も観戦のみ。
- 初期実装では、切断プレイヤーは即脱落扱い。
- 将来的に再接続対応を検討する。

## 5. ロビー / 設定

### 5.1 ロビーで変更可能な設定

- モード
- 必要ラウンド勝利数
- Draft 提示枚数
- Draft 取得枚数
- フレンドリーファイア
- マップローテーション
- 外周境界の収縮速度
- 外周境界ダメージ倍率
- Draft 制限時間の有無

### 5.2 チーム分け

- チーム戦では以下に対応する。
  - ロビーでプレイヤーが自分のチームを選ぶ
  - マッチ開始時にランダムでチーム分けする
- ホストによる個別割り当ては初期範囲外。

### 5.3 非対称チーム

- 最大 4 人の範囲で非対称チームを許可する。
- 1v2 と 1v3 を可能とする。
- 人数差のバランスはカード取得枚数で調整する。

## 6. マップ / スポーン / 外周境界

### 6.1 マップ

- マップには射線を切れる壁や障害物を置く。
- 様々な形状のマップを用意する。
- 初期マップは 3 個。以後追加する。
- 初期マップは壁と障害物のみ。
- マップギミックは後から追加する。

### 6.2 マップ選択

- ロビーでマッププールを選ぶ。
- セットごとにマッププールからランダムにマップを選択する。
- 直前と同じマップは避ける。

### 6.3 スポーン

- マップごとに固定スポーン地点を用意する。
- チーム戦では味方同士が近く、敵チームとは離れる配置にする。
- カウントダウン中に敵同士が接触しないよう、スポーン位置とマップ設計で距離を確保する。

### 6.4 セット開始カウントダウン

- Draft 完了後は Ready 確認なし。
- 即座に 3 秒の開始カウントダウンへ入り、次セットまたは次ラウンドを開始する。
- カウントダウン中は移動のみ可能。
- カウントダウン中は射撃とシールド不可。
- カウントダウン中の移動範囲は制限しない。
- カウントダウン中もプレイヤー同士の接触と押し合いは有効。
- セット開始直後の無敵時間は基本なし。
- 開始事故はスポーン距離とマップ設計で防ぐ。

### 6.5 外周境界

- セット開始時は、マップ外周がダメージ境界となる。
- セット開始 30 秒後から、ダメージ判定を持つ外周境界が中央へ収縮する。
- 外周境界はプレイヤーを押し返す。
- 境界より外には出られない。
- 境界に触れ続けている間、継続ダメージを受ける。
- 外周境界は最終的にプレイヤー 1 人分程度の範囲まで縮む。
- 収縮開始から最小サイズ到達までの時間は調整前提。初期仮値は 60 秒。
- ダメージ量は調整前提。初期は収縮進行度に応じて連続的に増加する。
- 弾が外周境界に当たった場合は壁と同じ扱い。
- 通常弾は消滅し、反射などの例外はカードごとに定義する。

## 7. 視界 / 情報公開

- 全域可視。索敵要素は入れない。
- 位置取りと射線管理を重視する。
- 全員の取得カード一覧を確認可能。
- 自分と敵の HP バーを表示する。
- 全プレイヤーの弾数とリロード状態を表示する。
- シールドのクールダウンや使用可能状態も全プレイヤーに表示する。

## 8. 戦闘バランス

### 8.1 基礎ステータス

- 基礎 HP は調整前提。初期仮値は 100。
- 通常移動速度は調整前提。初期は標準速度とし、距離があれば弾を避けられる程度にする。

### 8.2 キルタイム

- バニラ状態の実戦キルタイムは 3 ～ 5 秒を目標とする。
- バニラ状態では 4 発キルを基準にする。
- HP 100 の場合、初期仮値は 1 発 25 ダメージ。

### 8.3 初期武器

- 初期武器は単発セミオート。
- 入力ごとに 1 発発射する。
- 最短射撃間隔は調整前提。初期仮値は 0.75 秒。
- 初期弾は中速。距離があれば避けられる速度感にする。
- 初期武器には弾数とリロードがある。
- マガジン弾数は調整前提。初期仮値は 6 発。
- リロード時間は調整前提。初期仮値は 1.5 秒。
- リロードは弾切れ時の自動リロードのみ。
- 手動リロードボタンは設けない。
- 弾切れになった瞬間に自動リロードを開始する。
- リロード中は移動とシールドが可能。射撃だけ不可。

### 8.4 回復設計

- 単純回復は弱めにする。
- ドレイン効果は多少強くしてよい。

### 8.5 ノックバック

- 被弾時のノックバックは、命中した弾の弾速に比例する。
- ノックバック上限は設けない。
- 弾速を上げるカードによって、派手に吹き飛ばせるようにする。
- プレイヤー同士の接触ではダメージなし。押し合いのみ。

### 8.6 フレンドリーファイア

- チーム戦のフレンドリーファイアは設定で切り替え可能。
- 標準では味方にも命中する。
- 味方へのダメージは減衰する。
- 減衰率は調整前提。初期仮値は 50%。

### 8.7 自傷

- 発射時点の自弾は自分に当たらない。
- 反射や分裂などで戻ってきた自分の弾は、自分にも当たる。

## 9. 弾 / 当たり判定

### 9.1 通常弾

- 通常弾はプレイヤーに命中したら消滅する。
- 反射や貫通などを持っていても、プレイヤーに命中した場合は消滅する。
- そのため、同じ弾が同じプレイヤーに再命中することはない。

### 9.2 壁 / 外周境界

- 通常弾は壁や外周境界に当たると消滅する。
- 反射、貫通などの例外と優先順位はカードごとに定義する。

### 9.3 分裂弾

- 分裂後の弾 1 つ 1 つを別々の弾として扱う。

### 9.4 ヒット間隔

- 通常ルールでは、プレイヤー命中時に弾が消滅するため、同一弾による多段ヒットは発生しない。
- 分裂弾や特殊効果による複数ヒットは、それぞれ別弾またはカード効果として扱う。

## 10. カードシステム

### 10.1 Draft タイミング

- マッチ開始直後、最初のセット前に全員が初回 Draft を行う。
- ラウンド終了直後、次ラウンド開始前にラウンド敗者が追加 Draft を行う。
- FFA では、ラウンド勝者以外の全員が追加 Draft 対象となる。
- 敗者追加 Draft 後も、勝者側への補償はない。

### 10.2 Draft 枚数

- Draft の提示枚数と取得枚数は設定で可変。
- 標準は 3 枚提示 / 1 枚取得。
- 1 回の Draft 内で同じカードは複数提示されない。
- Draft カードの再抽選は不可。
- 取得済みの重複不可カードは、以後の Draft 候補に出ない。
- Draft 候補不足は仕様上起こさない設計にする。
- 重複可能カードを十分に用意し、提示枚数を満たせるカードプールにする。

### 10.3 非対称チームの Draft 補正

- 非対称チームでは、チーム総取得枚数が同じになるように Draft 枚数を補正する。
- 多人数側は各プレイヤーが 1 枚取得する。
- 1v2 の場合、1 人側は 2 枚取得する。
- 1v3 の場合、1 人側は 3 枚取得する。
- 複数枚取得する場合は、通常 Draft を取得枚数ぶん繰り返す。
- 例: 1v3 の 1 人側は、3 枚提示 / 1 枚取得を 3 回行う。

### 10.4 Draft 制限時間

- Draft 制限時間はロビー設定で切り替え可能。
- 標準は制限時間なし。
- 制限時間ありで時間切れになった場合、現在選択中またはマウスオーバー中のカードを取得する。
- 選択中またはマウスオーバー中のカードがない場合は、ランダムに 1 枚取得する。
- Draft 中、他プレイヤーが選んだカードは全員に即時公開される。

### 10.5 カード適用タイミング

- カード取得直後に UI 上は反映する。
- 実戦効果は次セット開始時のビルド適用フェーズで適用する。

### 10.6 カード保持

- 取得したカードはマッチ終了まで永続。

### 10.7 重複取得

- 同じカードの重複取得は一部カードのみ可能。
- 重複可能カードは基本加算で効果を積み上げる。
- 必要なカードだけ個別に乗算、上限、特殊処理を持つ。

### 10.8 効果適用順

- 基本の適用順:
  1. 基礎値
  2. 加算補正
  3. 乗算補正
  4. 上限 / 下限
  5. 特殊効果
- 例外カードだけ個別処理を行う。

### 10.9 レアリティ

- 初期レアリティは 3 段階。
  - 通常
  - レア
  - レジェンド
- 必要なら後から段階を増やす。
- レアリティ出現率は調整前提。
- 初期仮値:
  - 通常 70%
  - レア 25%
  - レジェンド 5%
- マッチ全体の勝敗や連敗状況によるレアリティ補正は行わない。

### 10.10 カード色 / 枠

- カード本体の色で効果カテゴリを表す。
- カード枠の色でレアリティを表す。
- 初期カテゴリ:
  - 赤: 攻撃
  - 青: 防御
  - 緑: 移動
  - 黄: サブ行動
  - 紫: 特殊

### 10.11 初期カード数

- 初期カード数は 20 枚前後。
- 5 カテゴリごとに数枚ずつ用意する。

### 10.12 カード設計方針

- 何かの能力を上げるカードには、急激なインフレを防ぐためにトレードオフを持たせる。
- 例: 威力アップと引き換えに発射間隔が長くなる。
- ただし、総合的にはプラスとなるように設計する。
- サブ行動カードはシールドへの効果追加または強化のみとし、サブ行動そのものの置換は行わない。
